A solution is not its code. A solution.yml describes what an owner offers for reuse. The code that implements it, if any, is listed under codebases, and each public codebase is described by its own publiccode.yml. How they relate

Web addresses

FieldMeaning
service_urlThe live service itself: where people start using it (start page, sign-in, application, or base API address)
service_page_urlThe owner's public page describing the service
documentation_urlTechnical or implementation documentation

All three are recommended for every record.

Optional fields

codebases (repository URL, visibility, publiccode.yml URL, maintenance, version, maintainers), open_data (title, catalogue URL, catalogue name), access_restriction, service_url, service_page_url, documentation_url, current_version, roadmap_url, dependencies, related_assets, adopters (self-reported or verified), standards_alignment, accessibility_statement_url, funding_model.

Added by the register

Never written in a solution.yml: last_changed, history_url, merged_in, currency, hosting, source, harvested_at, content_hash, source_state.

Pointer records

An owner-hosted record is registered with three fields: id, source (HTTPS URL of the owner's solution.yml) and expected_owner.
