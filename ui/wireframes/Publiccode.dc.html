Standards reuse

Solutions, codebases and publiccode.yml

A common solution is what an owner offers for reuse. Its code, if it has any, is one or more codebases. The register describes solutions with solution.yml, and links to their codebases, which keep using the European publiccode.yml standard unchanged.

solution.ymlpubliccode.yml
DescribesA common solution: what is offered, by whom, and how to adopt itA codebase: one software repository
LivesWherever the owner chooses, or in the registerAt the root of the codebase's repository
How manyOne per solutionOne per codebase. A solution may have none, one or several.
RelationshipLists its codebasesValidated by the register when a solution links to it

Worked example: this demonstrator

The register is a service (record csr-0001). The repository that builds it is its codebase. Official parser result for that codebase: Valid [parser version, date]

solution.yml (the solution)

id: csr-0001
name: Common Solution Register Demonstrator
asset_type: service
status: in-development
owner:
  organisation: The Digital Office for
                Scottish Local Government
service_url: https://the-digital-office.github.io/
             common-solution-register/
adoption_route:
  summary: Browse, query or contribute ...
codebases:
  - repository_url: https://github.com/
      The-Digital-Office/common-solution-register
    visibility: public
    publiccode_url: [...]/publiccode.yml
    maintenance: internal
open_data:
  - title: Register records
    url: [...]/data/register.json

What the register takes from a codebase's publiccode.yml

publiccode.ymlsolution.ymlTreatment
urlcodebases[].repository_urlCopied
maintenance.typecodebases[].maintenanceCopied: internal, contract, community or none
softwareVersioncodebases[].versionCopied
maintenance.contactscodebases[].maintainersName, affiliation and email; phone not imported
name, description, developmentStatus, landingURL, legal.licenseSolution name, summary, purpose, status, service page, termsSuggested only when drafting a new solution: the owner confirms or changes them, because a codebase's description is not necessarily the solution's
categories(none)Shown as hints for choosing capabilities

A public repository on its own is not a common solution. The register lists it only as a codebase of a solution that someone offers for reuse.
